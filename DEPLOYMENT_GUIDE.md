## 🎯 **Step-by-Step Deployment**

### **Step 1: Create Render Account & Connect GitHub**

1. Go to [render.com](https://render.com) and sign up (use GitHub sign-in)
2. Click **"New +"** → **"Blueprint"**
3. Connect your GitHub repository containing MESOB HRMS
4. Grant Render access to your repository

### **Step 2: Deploy Using Blueprint (render.yaml)**

1. After connecting GitHub, Render will detect `render.yaml`
2. Click **"Apply"** to create all services automatically
3. Render will create:
   - ✅ Database (MariaDB/MySQL)
   - ✅ Backend API Service
   - ✅ Frontend Static Site

### **Step 3: Configure Environment Variables**

#### **A. Backend Service Environment Variables**

Go to **mesob-hrms-backend** service → **Environment** tab:

**Database (Auto-populated by Render):**
- `DB_HOST` - ✅ Auto-filled
- `DB_USER` - ✅ Auto-filled
- `DB_PASSWORD` - ✅ Auto-filled
- `DB_NAME` - ✅ Auto-filled

**JWT Secrets (Auto-generated by Render):**
- `JWT_SECRET` - ✅ Auto-generated
- `JWT_REFRESH_SECRET` - ✅ Auto-generated

**MinIO Configuration (You need to set these - see Step 4):**
```
MINIO_ENDPOINT=<your-minio-url>
MINIO_PORT=443
MINIO_USE_SSL=true
MINIO_ACCESS_KEY=<your-minio-access-key>
MINIO_SECRET_KEY=<your-minio-secret-key>
MINIO_BUCKET=mesob-hrms
```

**Frontend URL (Update after frontend deploys):**
```
FRONTEND_URL=https://mesob-hrms.onrender.com
CORS_ORIGIN=https://mesob-hrms.onrender.com
```

#### **B. Frontend Service Environment Variables**

Go to **mesob-hrms-frontend** service → **Environment** tab:

```
VITE_API_URL=https://mesob-hrms-backend.onrender.com
```

### **Step 4: Set Up MinIO Object Storage**

**Option A: Use MinIO Cloud (Recommended for Production)**
1. Sign up at [min.io](https://min.io/pricing)
2. Create a bucket named `mesob-hrms`
3. Get access key and secret key
4. Add credentials to backend environment variables

**Option B: Use AWS S3 (Alternative)**
1. Create AWS account and S3 bucket
2. Get IAM credentials with S3 permissions
3. Update backend code to use S3 SDK instead of MinIO

**Option C: Self-host MinIO (Not Recommended for Free Tier)**
1. Deploy MinIO on another Render service or external server
2. Use the MinIO URL as `MINIO_ENDPOINT`

**For Development/Testing (Temporary):**
You can temporarily disable file uploads by setting:
```
MINIO_ENDPOINT=localhost
MINIO_PORT=9000
MINIO_USE_SSL=false
```
⚠️ **Warning**: This will cause file upload failures but won't crash the app

### **Step 5: Initialize Database**

After backend deploys successfully:

1. Go to **mesob-hrms-backend** service → **Shell** tab
2. Run database initialization:

```bash
cd backend
npm run db:init
```

This will:
- Create all database tables
- Set up default data
- Create default admin user

**Default Login Credentials:**

- Password: `mesob2024`

### **Step 6: Update URLs**

After both services deploy, update the URLs:

**Backend Environment:**
```
FRONTEND_URL=https://mesob-hrms.onrender.com
CORS_ORIGIN=https://mesob-hrms.onrender.com
```

**Frontend Environment:**
```

```

**In render.yaml (for future deployments):**

### **Step 7: Trigger Redeploy**

After updating environment variables:
1. Go to each service
2. Click **"Manual Deploy"** → **"Deploy latest commit"**
3. Wait for both services to redeploy

## 🔧 **Common Issues & Solutions**

### **Issue 1: Backend Not Starting**

**Error**: "Cannot connect to database"

**Solution**:
1. Check database is running: Dashboard → **mesob-hrms-db**
2. Verify environment variables are set
3. Check backend logs for specific error

### **Issue 2: Frontend Shows "Network Error"**

**Solution**:
1. Check `VITE_API_URL` in frontend environment
2. Verify backend is running and healthy
3. Check CORS configuration in backend

### **Issue 3: File Upload Fails**

**Solution**:
1. Verify MinIO configuration in backend environment
2. Check MinIO/S3 bucket exists and is accessible
3. Verify access keys have write permissions

### **Issue 4: "Invalid Token" After Login**

**Solution**:
1. Verify JWT secrets are set in backend
2. Check frontend and backend URLs match in CORS
3. Clear browser cookies and try again

### **Issue 5: Free Tier Limitations**

**Render Free Tier Limits:**
- Services spin down after 15 minutes of inactivity
- First request after spin-down takes 30-60 seconds
- 750 hours/month across all services
- Database limited to 256MB

**Solutions:**
- Upgrade to Starter plan ($7/month per service)
- Use external cron job to ping health endpoint every 10 minutes
- Consider upgrading database for production use

## 📊 **Database Management**

### **Access Database Shell**

Go to **mesob-hrms-db** → **Shell** tab:

```bash
# Connect to MySQL
mysql -u $MYSQL_USER -p$MYSQL_PASSWORD $MYSQL_DATABASE

# Show tables
SHOW TABLES;

# Check users
SELECT username, role FROM Users;
```

### **Backup Database**

```bash
# In database shell
mysqldump -u $MYSQL_USER -p$MYSQL_PASSWORD $MYSQL_DATABASE > backup.sql
```

### **Reset Database**

```bash
# In backend shell
npm run db:clean
npm run db:init
```

## 🔐 **Security Recommendations**

### **Before Going to Production:**

1. **Change Default Passwords**
   - Update all user passwords from `mesob2024`
   - Use strong, unique passwords

2. **Update JWT Secrets**
   - Generate new strong secrets in Render dashboard
   - Never commit secrets to Git

3. **Enable HTTPS Only**
   - Render provides free SSL certificates
   - Ensure `MINIO_USE_SSL=true` for MinIO

4. **Set Up Rate Limiting**
   - Already configured in backend
   - Monitor for abuse

5. **Enable Database Backups**
   - Render provides automatic backups on paid plans
   - Set up external backup solution for free tier

6. **Monitor Logs**
   - Check logs regularly for errors
   - Set up alerts for critical errors
